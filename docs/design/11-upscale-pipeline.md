# 11. 復号からアップスケールまでの詳細設計（#5・#6・#7・#8 の横断）

対象: 復号済みフレーム（NV12）から、deinterlace・前処理・AI 超解像（SR）・最終拡大を経て drawable に描くまでの処理と、その実行計画。05（Metal）・06（Core ML）・07（強調）の方針を、**現状のコードと突き合わせて**具体的な寸法・形式・スケジュールに落とす。

この文書は設計の提案であり、§3 の「決定待ち」はユーザーの判断で確定する。確定した項目は 10 の決定ログに移し、05・07 の該当節を改める。

## 1. 前提と範囲

- 入力: DVD / ファイルの SD 映像。NTSC 720×480（29.97、interlaced または telecine）、PAL 720×576（25）。MPEG-2 の 4:2:0、BT.601、video range。
- 出力: Retina の drawable（窓・全画面。1080p〜4K 相当の画素数）。
- 範囲: 取り込み、field 処理、前処理（ノイズ・ブロック）、色変換、SR、SR 後処理、最終拡大、字幕・メニューの重ね合わせ、提示の順序と時間管理。
- 範囲外: モデルの学習。変換環境（OQ-07）は手順だけ扱う。24p の再提示（OQ-10）は §6.4 で関係だけ述べる。
- 実盤で確定している事実（決定ログ 2026-11-20。PR #52 で main に入る）:
  - 実盤 PICHI は top-first・フレーム符号化・SAR 8:9（AVFoundation の `sampleAspect` は 10:11）。合成素材は bottom-first。
  - idet では純粋な 3:2 でも 2:2 でもない混在（アニメ）。
  - `MetalRenderGraph.swift:254` は順序 `unknown` を top-first とみなす。

## 4. 寸法と画素数（SR 2 倍の場合）

D2 の推奨（元格子のまま SR）で計算する。() は 07 §2 の正規化方式。

| 入力 | 取り込み域（cleanAperture） | 画素数 | SR 出力 | 正方画素での表示寸法 |
|---|---|---|---|---|
| NTSC 4:3 | 704×480 | 337,920（正規化 720×540 なら 388,800、+15%） | 1408×960（正規化なら 1440×1080） | 640×480 |
| NTSC 16:9 スクイーズ | 704×480 | 337,920（正規化 854×480 なら 409,920、+21%） | 1408×960 | 854×480 |
| PAL 4:3 | 704×576 | 405,504 | 1408×1152 | 768×576 |
| IVTC 後の film（23.976p） | 704×480 | 337,920 | 1408×960 | 640×480 |

最終拡大の倍率（SR 出力 → drawable 内の映像矩形。横 / 縦）:

| 入力 | 1080p（映像 1440×1080 / 16:9 は 1920×1080） | 1440p | 4K |
|---|---|---|---|
| NTSC 4:3 | 1.023 / 1.125 | 1.364 / 1.5 | 2.045 / 2.25 |
| NTSC 16:9 | 1.364 / 1.125 | 1.818 / 1.5 | 2.727 / 2.25 |
| PAL 4:3 | 1.023 / **0.9375（縮小）** | 1.364 / 1.25 | 2.045 / 1.875 |

- PAL を 1080p に出すと縦は縮小になる。最終拡大は縮小側のフィルタ（§5.6）も要る。
- 4K では SR の後にさらに約 2 倍の拡大が残る。07 §2 のとおり、AI 段を 2 段重ねない。

SR に要る処理量（入力画素 / 秒）:

| 入力 | フレーム周期 | 入力画素 / 秒 |
|---|---|---|
| NTSC 29.97 | 33.37 ms | 約 10.1 M |
| IVTC 23.976 | 41.71 ms | 約 8.1 M |
| NTSC 59.94（field レート） | 16.68 ms | 約 20.3 M |
| PAL 25 | 40.00 ms | 約 10.1 M |

`FrameBudget.initialDraft` の `inferenceMS` 18 ms は、29.97 の周期 33.37 ms の中で他の段と**直列**に並べた値。§6 の先読みでは、SR（ANE）は GPU の段と並行に走る。そのため制約は「1 フレームの直列の合計」から、「SR の 1 フレームあたり占有時間 < フレーム周期」と「先読みの深さ × 周期 > SR の遅延」の 2 つに変わる。`FrameBudget` はこの 2 つを表せる形に改める（§9 の P4）。

## 5. 段の設計（目標の形）

```
NV12（復号）
 → [GPU] 取り込み（zero-copy）
 → [GPU] field 処理: motionAdaptive / IVTC（輝度と色差を field ごと。D8）
 → [GPU] SR 前のアーティファクト除去（YCbCr。ブロック・リンギング・色ノイズ。弱め。D1）
 → [GPU] 色変換 + 色差の補間（4:2:0 → 4:4:4、MPEG-2 の配置）+ 切り出し → RGB 16F（元格子。D2・D3）
 → [ANE / GPU] SR ×2（全画面の固定寸法。予備は GPU タイル。D4）
 → [GPU] SR 後処理（任意: 時間安定化。§7）
 → [GPU] 最終拡大（PAR 補正 + 表示寸法。拡大は Catmull-Rom、縮小は面積平均）→ drawable
 → [GPU] 字幕・メニューの重ね合わせ（drawable 上。SR とは独立）
 → present
```

非 AI 経路（tier `.metalOnly`）は SR の段を抜くだけで、それ以外は同じ（INV-2）。現状の「色変換 + 拡大を 1 pass」は非 AI 経路の最適化として残す。

### 5.1 field 処理

- 輝度は現状のまま（motionAdaptive が既定。前フレームが無ければ edgeDirected）。
- **色差を field ごとに処理する（D8）**:
  - interlaced の 4:2:0 では、色差の各行は交互に top / bottom field に属する。
  - motionAdaptive（動く画素は保持 field の色差から補間）と IVTC（field 規則で織る）は対応済み。
  - edgeDirected と bob も、輝度で保持した field の色差の行だけから作るように直す（前 frame が無いので全画素を「動き」とみなすのと同じ）。
- 検査: 動く色の縦縞の合成素材で、色差の comb を数値で測る（§10）。

### 5.2 SR 前のアーティファクト除去（D1）

- YCbCr のまま（現状の位置）で、ブロック（8 px 境界の段差）、リンギング、色ノイズを弱く除く。
- 既定の強さは 07 §3 の保守的な値（0.35 以下）。粒子（grain）と線画は保護する（07 §3 の `protect`）。
- 目的は「SR が増幅する前に消す」ことに限る。ぼかしで細部を消さない。

### 5.3 色変換と色差の補間

- BT.601 の行列、video range → full range（現状の `ColorMatrixBuilder`）。
- 色差の補間位置は MPEG-2 の 4:2:0 の配置（横は輝度と同位置、縦は 2 行の間）。現状の linear sample の位置が合っているかは、合成の色の縁の素材で確かめる（05 §3 の「自力で sample 位置を決める」）。
- 出力は元格子（cleanAperture）の RGB 16F。gamma は線形化しない（05 §3 の既定。モデルの学習前処理に合わせる。06 §4）。

### 5.4 SR（D2・D3・D4）

- **モデル契約**（06 §2 の manifest に記載）:
  - 入力は RGB、16 bit 浮動小数、0..1、NCHW。
  - 形状は入力の種類ごとの固定寸法（EnumeratedShapes: 480×704、480×720、576×704、576×720）。
  - 出力は 2 倍。
- **橋渡し**:
  - GPU が IOSurface 付きの 16 bit 単成分 buffer（高さ 3H の planar = NCHW）に書き、それを MLMultiArray として Core ML に渡す。
  - 出力も `outputBackings` で同じ形の buffer を渡し、GPU が読む。
  - この経路の API（`MLMultiArray(pixelBuffer:shape:)` と、ANE で zero-copy になるか）は **SDK と実測で要確認**。だめなら 06 §4 の方針 A（BGRA の CVPixelBuffer）に 16 bit 版で戻す。
- **タイル（予備）**:
  - モデルが全画面の形状を受けない（変換できない・ANE に載らない）場合だけ使う。
  - 切り出しと feather 合成は GPU compute に移す（現状の CPU の `[Float]` は SD でも 1 frame あたり数百万要素で、実時間に向かない）。
  - タイルは 1 回の予測にまとめる（batch 次元）。
- **計算単位**: ANE を第 1 候補にする。GPU は Metal の段と取り合うため。ANE / GPU / 自動を G3 で実測して決める（06 §5）。
- **候補のモデルの種類**（モデルは決めない。重みの権利は OQ-07 / OQ-11 で未解決）:

| 種類 | 例 | 計算量の概算（**計算値。実測ではない**） | 位置づけ |
|---|---|---|---|
| 軽量・アニメ向け ×2 | SRVGG compact 系（64 ch、3×3 conv 16 層） | 入力 1 画素あたり約 1.18 MFLOP → 704×480 で約 0.40 TFLOP / frame → 29.97 で約 12 TFLOPS | 実時間の第 1 候補。32 ch の縮小版なら約 1/4（約 3 TFLOPS） |
| 軽量・一般向け ×2 | 同系の実写向け | 同程度 | 実写素材用 |
| 重い・一般向け | RRDB 系（Real-ESRGAN x2plus。パラメータ約 16.7M、本体は 1/2 解像度） | 入力 1 画素あたり約 8.4 MFLOP → 約 2.8 TFLOP / frame → 29.97 で約 85 TFLOPS | 実時間は見込めない。**一時停止中の 1 枚**（§6.3）か非実時間の用途 |

  - 計算量は構成（層数・ch 数）からの理論値で、ANE / GPU の実効性能と利用率は含まない。実時間に収まるかは G3 の実測で決め、収まらなければ OQ-14 の方針（非 AI を標準にする）に従う。
  - テスト素材の実盤 PICHI はアニメなので、評価の第 1 候補は「軽量・アニメ向け」。実写の素材（#15 の pending）が揃うまで、一般向けの評価は保留する。

### 5.5 SR 後処理

- 既定はなし。
- 任意で時間安定化（07 §4 の `temporalBlend = .light`）を置く。動きマップは field 処理の段から受け取る。
- SR の後に輪郭強調をかけない（AI の出力にさらに強調をかけるとリンギングが出る）。

### 5.6 最終拡大

- SR 出力（または非 AI 経路の元格子）から、drawable の映像矩形（letterbox 込み）へ 1 回で拡大する。PAR 補正もこの 1 回に含める。
- 拡大（倍率 > 1）は Catmull-Rom（現状の非 AI 経路と同じカーネルを RGB 入力用にも用意する）。
- 縮小（PAL の 1080p の縦など）は面積平均（box / bilinear の mip ではなく、倍率に合わせた tap 数）。
- 現状の `rv_rgbPresent_v1`（1 回の sample）は置き換える。
- 8 bit の drawable へ書く時点で軽いディザ（16F → 8 bit の段差対策）。

### 5.7 字幕・メニュー

- 字幕・メニューは、映像の最終拡大の後に drawable 上で重ねる（PR #53 の `drawOverlay` の位置。05 §4 の「合成 → 最終拡大」とは逆で、D10 で決める）。SR の後に置く点は 04 §7・05 §4 と同じ。重ね合わせは映像と同じ geometry を使うので、SR の有無や SR 出力の寸法に影響されない。
- SR・時間安定化に字幕を巻き込まない（滲みを避ける）。
- 本編の字幕（タイトルの SPU）は未実装で、同じ経路に載せる。

### 5.8 表示の色空間

- 現状は `CAMetalLayer.colorspace` にタグが無い。SD の原色（SMPTE-C / EBU）と BT.709 / sRGB の差は小さいが、ディスプレイの色域（P3）で色が広がって見える可能性がある。
- **要確認**: タグなしの層がどう扱われるかを実機で確かめ、sRGB（BT.709）のタグを付けるか決める。原色の変換（601 → 709）は差が小さいので後回しにする。

## 6. 実行の時間管理（D5）

### 6.1 先読みキュー

- 復号は再生位置より N frame（初期値 3）先まで進める（現状の復号の先読みに相乗りする）。
- 復号された frame ごとに、前処理（GPU）→ SR（ANE）を**提示より前に**投入する。結果は `FrameID` で保持する。
- 提示（PTS どおり、音声が主時計 — INV-1）の時点で:
  - SR の結果があればそれを使う。
  - 無ければ非 AI 経路で描く（待たない）。
- 期限: `presentTime(PTS) − 後処理と提示の予算 − 余裕`（06 §7）。期限に間に合わない見込みの job は投入しない。
- 並行数: ANE の job は最大 2（06 §7・00 §5）。

### 6.2 強調 / 非強調の切り替え（ちらつき対策）

- frame ごとに強調と非強調が交互に出ると、質感が毎秒変わって見える。そこで「強調中」の状態を持つ。
- 強調中でも、間に合わない frame は非強調で出す（止めない）。ただし直近 1 秒の取りこぼし率が 5% を超えたら、強調を **10 秒止める**（08 の降格に載せる）。
- 再開時は先読みが埋まってから切り替える。
- 数値は初期値で、実測で詰める。

### 6.3 シーク・一時停止・コマ送り・速度

| 操作 | 挙動 |
|---|---|
| シーク | 世代番号を進め、古い世代の job と結果を捨てる。再開直後は非強調で出し、先読みが埋まったら強調へ（§6.2） |
| 一時停止 | 表示中の frame を**期限なし**で SR し、終わったら描き直す（一時停止中は画質優先）。重いモデルがあれば、ここでだけ使う選択肢を残す |
| コマ送り | 一時停止と同じ（1 枚ごとに期限なし） |
| 速度 ≠ 1 | SR を止める（周期が変わり予算が崩れるため） |
| DVD メニューの静止画 | SR を 1 回だけ行い、結果を (item, planHash) で保持する。メニューの重ね合わせは独立（§5.7）なので、ボタン操作で SR をやり直さない |

### 6.4 IVTC との関係（D7）

- telecine を検出して field を組み直した frame（`TelecineMatcher`）は、元の film の 1 コマに対応する。
- 直前の frame と同じコマなら SR をせず、結果を再利用する。
- 24p の再提示（OQ-10）とは独立に効く。

## 7. 時間方向の安定性

- SR は frame ごとに独立なので、細部（線の太さ・模様）が frame 間で揺れることがある（R3）。
- 測定: 静止した領域（動きマップが 0 の block）で、連続 frame の差分の分散を「フリッカ指数」として測る。実盤の切り出し素材（`animation-480i-01`）で、非 AI と各モデルを比べる（§10）。
- 対策の順: (1) モデルの選択（時間安定性の良いもの）、(2) §5.5 の時間安定化、(3) 強調の強さ（SR 出力と非 AI 出力の線形合成）。

## 8. 計測

| 測るもの | 方法 |
|---|---|
| 段ごとの GPU 時間 | `MTLCounterSampleBuffer`（05 §8） |
| SR の遅延と占有時間 | job の投入〜完了（host time）。p50 / p95 |
| 橋渡しのコスト | 16F の書き込み・読み出しを SR と分けて測る（06 §4） |
| 取りこぼし率 | 提示時に SR の結果が無かった frame の割合 |
| end-to-end 遅延 | PTS が media clock に現れてから `presentedTime` まで（05 §8 の定義） |
| フリッカ指数 | §7 |
